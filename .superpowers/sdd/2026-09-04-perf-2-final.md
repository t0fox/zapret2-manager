Status: `IMPLEMENTED_WITH_UNPROVEN_ACCEPTANCE_GATES`. The RPC/UI regression and
the PERF-2 transport work are implemented and verified. This report does not

## Root cause

The failure was one RPC/state transport regression with several amplifiers:

1. LuCI loaded multiple reads for the same canonical state in parallel. DNS
   opened the product snapshot plus status, low-level DNS, service DNS and
   global DNS owners, then opened provider owners again. Strategies opened a
   second `status_fast` read while the application shell was already reading
   it. On the real router, rpcd serialized enough of this fan-out that later
   calls timed out or returned rejected RPC frames.
2. Dashboard deferred work had only a flat queue. Slow preview,
   recommendations and remote metadata could occupy both deferred slots while
   events and active-strategy state were still waiting.
3. The application header kept routine polling alive for hidden tabs and did
   not seed the status broker from the shell result. Navigation and visibility
   transitions therefore reopened the same read.
4. Promise rejection paths then presented the transport/session copy instead
   of retaining the backend error envelope. That made rpcd starvation look
   like “LuCI session or network unavailable”. It was not a missing
   `zapret2-manager` object: the direct ubus object and required methods were
   present on the router.

The fix keeps backend errors as bounded normalized envelopes, establishes one
canonical owner per first-paint state, uses a seeded single-flight
`status_fast` broker, pauses hidden-tab polling, and schedules Dashboard work
by semantic priority lanes. Telegram health remains explicit and finite; it
is not started by ordinary navigation and cannot remain an unbounded pending
request.

The secondary strategy workflows were audited as part of the same regression:
automatic status, run-status, apply-operation, and Orchestra polling now update
their live module state through the app's local rerender bridge. Their error
states also rerender immediately. Full route refresh remains reserved for
mutations, confirmed history reloads, and explicit user navigation; a polling
tick no longer reopens the whole Strategy RPC fan-out.
